# Post-PoC plan (G8 to G11)

Date: 2026-11-12.

This directory is not the approved plan. It is a planning baseline for four
gates that stay inactive:

| Gate | Meaning |
| --- | --- |
| G8 | MVP entry: hygiene, productisation and profile registers |
| G9 | Functional MVP: completion of C1-C8 |
| G10 | Operational MVP: portability, security, recovery, load and tools |
| G11 | Production |

Every task has status `PLANNED_NOT_ACTIVE`. No task runs before the Product
Owner decision on G7. Extending the backlog schema, admitting these tasks into
the executable backlog, and moving rows in the traceability plan all wait on
`POST-POC-BACKLOG-ACTIVATION`. This README does not recommend a time for that
decision.

The approved backlog, the traceability plan, ADD v1.3, LLD v1.1, contracts,
schemas and `inputs/` are unchanged. Claims stay E1=0, E2=0, Verified=0,
runtime NOT_ESTABLISHED, PoC NO-GO and Production NO-GO.

The planning anchor is `2278be4180de5d91d1fec9d7608027b0f287b545`. Hashes of
the execution state and the conformance register are the blobs of that commit.
A later edit of those two files does not change the generated plan. The
generator reads the Requirement Register, the traceability plan and the
approved backlog from the working tree, and a change there fails the check.
The 2026-11-11 audit file is not on this baseline; adopted items are taken
from the normative decision `FABLE52-POST-POC-PROGRAMME (2026-11-11)`.

## Classification

The latest stage owns the single realise and verify pair.

- A release that contains Production or Future, or that equals "Ogni release",
  is G11.
- Otherwise a BR is G8, an FR or Funzionale requirement is G9, and an NFR or
  Non funzionale requirement is G10.
- A release of exactly PoC is out of this plan. The approved traceability
  target gate is left where it is.

Work is grouped by the owning workstream already recorded in the traceability
plan. Realise waves are 1, 3, 5 and 7. Each verify task depends on its realise
twin and sits on the following wave. A later realise wave depends on every
verify task of the previous gate.

## Files

- `OCOR_POST_POC_BACKLOG.json` holds the tasks.
- `OCOR_POST_POC_DEPENDENCY_GRAPH.json` holds the acyclic graph.
- `OCOR_POST_POC_REQUIREMENT_ALLOCATION.json` holds one row per beyond-PoC requirement.
- `OCOR_POST_POC_EXTERNAL_DECISIONS.json` lists decisions that this plan does not take.

Regenerate the four JSON files with `python3 scripts/validate_post_poc_plan.py --write`.
Check them with `python3 scripts/validate_post_poc_plan.py`.
